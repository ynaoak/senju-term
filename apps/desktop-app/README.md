# Senju Term

[Warp](https://github.com/warpdotdev/warp) にインスパイアされた、**カスタムコマンド(ワークフロー)管理**と **SSH 接続管理**を組み込んだクロスプラットフォームターミナルです。

- **実装言語**: Rust(バックエンド/コア)+ HTML/JS(描画は xterm.js)
- **対応 OS**: Windows / macOS / Linux(Tauri 2)
- ローカルシェルは [portable-pty](https://crates.io/crates/portable-pty)(Windows は ConPTY、Unix は openpty)
- SSH は [russh](https://crates.io/crates/russh)(Pure Rust。OpenSSL / libssh2 への依存なし)

## 主な機能

### ネイティブライクなカスタムタイトルバー
- **Windows / Linux**: OS 標準のウィンドウ枠(装飾)を無効化し、右上の最小化・最大化・閉じるをアプリ側で描画
- **macOS**: 装飾は残したままタイトルバーだけを透明化(`titleBarStyle: "Overlay"`)し、**OS 本物のトラフィックライト**をヘッダーに重ねて表示します。ヘッダーは左側を空けてボタンと重ならないようにしています(描画した偽のボタンは使いません)
- バー全体をドラッグでウィンドウ移動、ダブルクリックで最大化/復元
- 実行中のセッションがある状態で閉じようとすると確認します。macOS のトラフィックライトや `⌘W` など、アプリ側のボタン以外から閉じた場合も同じ確認が出ます
- **右クリックメニューの抑制**: テキスト入力欄(コピー&ペースト)とターミナル(ワークフロー起動メニュー)以外の場所 — ヘッダー・サイドバー・カードなど、実際に機能する項目が無い場所 — では、WebView 既定の右クリックメニュー(再読み込み/検証など)を表示しません
- **UI フォント**: アプリ全体(ターミナル本体を除く)の表示フォントは [Noto Sans](https://fonts.google.com/noto/specimen/Noto+Sans) / [Noto Sans JP](https://fonts.google.com/noto/specimen/Noto+Sans+JP) を `ui/vendor/fonts/` に同梱し自己ホスト。OS にフォントが入っていなくても、また CDN へアクセスできないオフライン環境でも同じ見た目になります(ターミナル本体のフォントは設定画面の「フォントファミリー」で別途指定する等幅フォントのままです)

### ターミナル / スレッド管理
- セッションを「スレッド」として左ペインで一覧管理(ローカルシェル / SSH が同居)。クリックで表示切替、非表示スレッドもバックグラウンドで動作し続けます
- **シェル操作はヘッダー左側に 1 つのグループ**としてまとまっています(スレッド一覧の開閉 ☰ / タスク / 上下分割 / 左右分割 / 一斉入力)。いずれもターミナルのペインに対する操作なので、**「シェル」タブを選んでいるときだけ表示**します。ワークフローなどのツールパネルを開いている間はペインが隠れていて何も起きないため、ボタン自体を出しません(ショートカットやパレットから実行した場合は、効果が見えるようシェル表示へ切り替えます)
- **動的タイトル**: シェルが OSC タイトル(`\e]0;...\a`)を送ると、スレッド名が自動で追従します
- **スレッド名のリネーム**: スレッド項目をダブルクリックでインライン編集(Enter で確定 / Escape でキャンセル)。空欄で確定すると自動タイトルに戻ります。リネームすると自動タイトル追従は止まります
- **スレッドの固定(ピン留め)**: 📍 ボタンでスレッドを左ペイン上部に固定。固定中のスレッドは一覧の先頭に並び、誤って閉じないよう終了時に確認します
- **非表示スレッドのアクティビティ表示**: 表示していないスレッドに出力があると、一覧のタイトル横に teal の●が点灯します
- **ペイン分割 — 上下**(`Ctrl+Shift+D`)**/ 左右**(`Ctrl+Shift+E`): 各ペインのヘッダーにあるドロップダウン、または左ペインのスレッド一覧から、どのスレッドを表示するか個別に選択可能。同じスレッドを両ペインが取り合った場合は自動でスワップ。境界はドラッグでリサイズ。分割中に反対方向のショートカットを押すと、ペインを閉じずにその場で向きだけ切り替わります
- **入力ブロードキャスト(一斉入力)**(`Ctrl+Shift+B`): 分割中にオンにすると、キー入力・貼り付けが表示中の全ペインへ同時に送られます(複数サーバーへの同一コマンド実行などに)。オン中は各ペインのヘッダーにアクセントカラーのラインが表示され、分割を解除すると自動でオフになります。パレットやワークフローからの実行はフォーカス中のペインのみが対象です
- **コピー & 貼り付け**(Windows / Linux は Windows Terminal と同じ操作): `Ctrl+V` / `Shift+Insert` / `Ctrl+Shift+V` で貼り付け、`Ctrl+C`(選択範囲があるときだけ。選択が無ければ従来どおり SIGINT)/ `Ctrl+Insert` / `Ctrl+Shift+C` でコピー(コピー後は選択を解除)。macOS は `⌘C` / `⌘V`
- **右クリックの動作**(設定 → ターミナル): 既定は Windows / Linux では「選択があればコピー(選択を解除)、無ければ貼り付け」、macOS ではワークフローのメニュー。**Shift+右クリック**ならどの設定でも常にメニューを開きます。メニューの先頭には「コピー」「貼り付け」が並びます
- **ターミナル内検索**(`Ctrl+Shift+F`): xterm.js の addon-search でスクロールバックを含めて文字列検索。前へ / 次へ移動可能
- **出力中のパスをクリック**: 出力に現れた**絶対パス**がリンクになり、クリックするとメニューが開いて「フォルダーで表示」/「パスをコピー」を選べます

  - 対象は絶対パスのみです(`/usr/local/bin`、`~/work/notes.md`、`C:\Users\...`、`\\server\share`)。`src/lib.rs` のような相対パスはリンクしません — 解決にはシェルの作業ディレクトリが必要で、まだ追跡していないためです(OSC 7 対応が入れば広げられます)
  - 末尾の句読点は含めず、`path.rs:42:13` のような行番号も外してパス部分だけをリンクします。URL は従来どおり addon-web-links が担当し、その中のパスを二重にリンクすることはありません
  - **「フォルダーで表示」はファイルマネージャーで場所を開くだけで、ファイルを既定のアプリで開くことはしません。** ターミナル出力は信用できない入力なので、既定のアプリに渡すと `.desktop` / `.command` / `.exe` などがそのまま実行されてしまいます(Windows は `explorer /select,`、macOS は `open -R`、Linux は親ディレクトリを `xdg-open`)
  - **右クリックからも開けます**: ターミナルを右クリックすると、**ポインタの下にあるパス**(またはパスだけを選択していればその選択)が右クリックメニューの先頭に出て、そこから「フォルダーで表示」/「パスをコピー」を実行できます。パスが無い場所ではこの項目自体が出ません。選択はポインタ位置より優先されるため、**リンクとして認識されなかったパスでも、選択してから右クリックすれば開けます**(選択が丸ごと 1 つのパスである場合に限ります — 文章の中に含まれるパスに対して勝手に動くことはありません)
  - **SSH スレッドではコピーのみ**を表示します。パスはサーバー側のファイルを指しているため、この PC で開くと無関係なファイルが開くか何も起きません。理由をその場に表示します。右クリックメニューでも同じ扱いです
- xterm.js による 256 色 / True Color 描画。フォントファミリー・スクロールバック行数(既定 10,000 行)は設定画面から変更可能
- **GPU レンダリング(WebGL)**: xterm の WebGL アドオンで描画を GPU 高速化(既定オン)。WebGL が使えない環境では自動で通常レンダラにフォールバックし、コンテキスト喪失時も安全に復帰します。設定「ターミナル > GPU レンダリング」でオフにでき、変更は開いているスレッドにも即時適用されます
- **ライト / ダークテーマ**: 設定画面の「外観 > テーマ」で切替。アプリ UI とターミナルの配色(ANSI カラー含む)が連動して切り替わります
- **ターミナルの配色プリセット / カスタム**: 設定「外観 > ターミナルの配色」で、UI テーマとは独立にターミナル本体の配色を選べます。組み込みプリセットは Solarized Dark / Solarized Light / Dracula / Nord / Gruvbox Dark / One Dark / Monokai / Tokyo Night / Catppuccin Mocha。「カスタム…」を選ぶと背景・文字・カーソル・ANSI 16 色をカラーピッカーで編集でき、プリセットからのコピーや UI テーマ配色へのリセットもできます。変更は開いているスレッドに即時プレビューされ、「保存」で確定します(`settings.json` の `term_theme` / `term_colors`)

### コマンドブロック(Warp 相当・シェル統合)
- シェルが [OSC 133](https://gitlab.freedesktop.org/Per_Bothner/specifications/blob/master/proposals/semantic-prompts.md) シーケンスを発行すると、コマンド単位の「ブロック」を認識します
- **終了ステータスチップ**: 実行を終えた各コマンドのプロンプト行の右端に ✓(成功)/ ✗ 終了コード(失敗)のバッジを表示
- **ブロックツールバー**: チップにマウスを重ねるとコピー・折りたたみボタンが表示されます
  - **コピー**: プロンプト行からそのコマンドの出力末尾までをまとめてクリップボードにコピー
  - **折りたたみ**: コマンド行は残したまま出力だけを畳んで隠す(再クリックで展開)。表示上のオーバーレイのみで、スクロールバックや検索の対象からは消えません
- **ブロック間ジャンプ**: `Ctrl+Alt+↑` / `Ctrl+Alt+↓` で前後のコマンドのプロンプト行へスクロール
- **長時間コマンドの完了通知**: 設定のしきい値(既定 10 秒)以上かかったコマンドが、**非表示のスレッド、またはウィンドウが非アクティブな時**に終わると、OS のデスクトップ通知(コマンド名・所要時間・終了コード)を出します。表示中のスレッドを前面で見ている時は通知しません。設定「ターミナル > 長時間コマンドの完了をデスクトップ通知」でオフ、しきい値も変更できます(ローカル / SSH を問わず OSC 133 を発行するシェルが対象)

#### シェル統合の自動有効化

ローカルシェルが **bash / zsh / fish** の場合、起動時に OSC 133(コマンドブロック)と [OSC 7](https://gitlab.freedesktop.org/terminal-wg/specifications/-/merge_requests/7)(作業ディレクトリの通知 — 後述の「タスク」ペインが使います)の連携フックを自動で組み込みます。ユーザーの `~/.bashrc` / `~/.zshrc` / `~/.config/fish/config.fish` は一切変更しません:

- **bash**: `--rcfile` で生成した一時 rcfile 経由(実行ファイル引数を明示的にカスタムしているプロファイルではスキップ)。中で `~/.bashrc` を先に source してから連携フックを追記します。「コマンド開始」マーカー(133;C)は bash 4.4 以降では `PS0`、それ以前(**macOS 同梱の bash 3.2 など**)では `DEBUG` トラップで発行します(既に `DEBUG` トラップが設定されている場合 — bash-preexec など — は上書きせず、そのままにします)
- **zsh**: `ZDOTDIR` を生成した一時ディレクトリへ向ける方式。`.zshenv` / `.zprofile` / `.zshrc` / `.zlogin` それぞれが実ホーム(または既存の `$ZDOTDIR`)の同名ファイルを source するプロキシになっており、ユーザーの設定は省略されません
- **fish**: `-C` (init-command) で connect — fish 自身の `config.fish` 読み込み後に追記実行されるだけなので、ファイル生成は不要です

設定画面の「ターミナル > シェル統合を自動で有効化」でオフにできます(既定は有効)。SSH 接続・カスタムプロファイル(bash/zsh/fish 以外の実行ファイル)には影響しません。

無効化した場合や、他のシェル/手動セットアップで OSC 133 を組み込みたい場合の設定例:

  **bash** (`~/.bashrc`, bash 4.4+):
  ```bash
  PS1='\[\e]133;A\a\]'"$PS1"'\[\e]133;B\a\]'
  PS0='\[\e]133;C\a\]'
  PROMPT_COMMAND='printf "\e]133;D;%s\a" "$?"'"${PROMPT_COMMAND:+;$PROMPT_COMMAND}"
  ```

  **zsh** (`~/.zshrc`):
  ```zsh
  precmd() { print -Pn '\e]133;D;%?\a\e]133;A\a' }
  preexec() { print -n '\e]133;C\a' }
  PS1="$PS1"$'%{\e]133;B\a%}'
  ```

  **fish** (`~/.config/fish/config.fish`):
  ```fish
  function __senju_blocks_prompt --on-event fish_prompt
      printf '\e]133;D;%s\a\e]133;A\a' $status
  end
  function __senju_blocks_preexec --on-event fish_preexec
      printf '\e]133;C\a'
  end
  ```

### ターミナルプロファイル(Windows Terminal 相当)
- 起動するシェルを「プロファイル」として登録・管理(名前 / 実行ファイル / 引数 / 作業ディレクトリ)
- 「＋ 新規」の **▾ メニューから起動するプロファイル、または登録済みの SSH 接続先を選択**(Windows Terminal のドロップダウン相当)。初回起動時に OS に応じた既定プロファイルを自動生成(Windows: PowerShell / コマンドプロンプト、Unix: bash / zsh / fish のうち存在するもの)
- **既定のプロファイルを設定可能**。「＋ 新規」ボタンやショートカットはこの既定プロファイルで起動します

### カスタムコマンド管理(Warp の Workflows 相当)
- コマンドテンプレートを名前・説明・タグ付きで登録/編集/削除/検索
- `{{名前}}` / `{{名前:既定値}}` 形式のプレースホルダに対応。実行時に入力ダイアログで値を埋めます
- **選択肢型プレースホルダ**: `{{名前|a,b,c}}` と書くと、実行時のダイアログがその選択肢だけのドロップダウンになります(先頭が既定)。`{{名前:b|a,b,c}}` で既定を指定できます(例: `deploy --env {{env|dev,staging,prod}}`)。選択肢はカンマ区切りで、前後の空白は無視されます。前回の入力値の記憶は、選択肢に含まれる値のときだけ効きます
- **組み込み変数**(`$` 始まり。入力なしで実行時に自動展開): `{{$cwd}}` 作業ディレクトリ(OSC 7)、`{{$host}}` / `{{$user}}` / `{{$port}}` 接続先(SSH スレッドのとき)、`{{$thread}}` スレッド名、`{{$date}}`(`2026-10-02`)/ `{{$time}}`(`13:05:00`)/ `{{$datetime}}`(`2026-10-02_13-05-00`、ファイル名向け)/ `{{$timestamp}}`(UNIX 秒)、`{{$selection}}` ターミナルの選択テキスト、`{{$clipboard}}` クリップボード。**テンプレートが参照している変数だけを解決する**ので、`{{$clipboard}}` を書いていないワークフローがクリップボードを読むことはありません。値が無い場合(ローカルで `{{$host}}` 等)は空になり、`{{$cwd:~}}` のように既定値を書けます
- 「実行」(Enter 送信つき)と「挿入」(入力欄に置くだけ)の 2 モード。複数行のコマンドテンプレートは「実行」時に行ごとに Enter を送信します(手で 1 行ずつ入力して Enter を押すのと同じ動作)。「挿入」は改行を含めそのまま入力欄に置くだけです
- **キーボードショートカット登録**(Ctrl / Alt / Meta を含む任意のキー)で、シェル表示中にワンキー実行
- **クイックボタン表示**: 各ワークフローを「シェル表示のクイック起動バー」にボタンとして常時表示できます
- **グループ管理**: 各ワークフローに「グループ」を割り当てて分類できます。グループは `/` 区切りで階層化でき(例: `Deploy/Staging`)、パネルはグループごとの見出しつきで表示されます
- **並べ替え**: 同じグループ内のワークフローを、カードの ▲ / ▼ ボタン、またはカード右下のグリップ(⠿)を掴んでの**ドラッグ&ドロップ**で並べ替えられます。ドロップ位置はカード端のアクセント線で表示されます(並び順は保存されます。別グループへのドロップは受け付けません)
- **書き出し / 取り込み(チーム共有)**: ワークフロー一式をバージョン付き JSON に書き出し、別マシンで取り込めます(Git リポジトリで共有する運用を想定)。取り込みはチェックリストで選択でき、既存(名前+コマンド一致)は「(登録済み)」表示で既定除外、既存とショートカットが重複する場合はショートカットを外して取り込みます。id は書き出し時に除去され、取り込み時に新規採番されるため既存を誤って上書きしません
- **右クリックの階層メニューから実行**: ターミナルを右クリックすると(パスの上ならその項目の下に)ワークフローのグループが階層(フライアウト)メニューになり、グループをたどって目的のワークフローを実行できます(クリックで実行 / Shift+クリックで挿入のみ)。→ / ← / ↑ / ↓ / Enter / Esc のキーボード操作にも対応。右クリックしたペインに対して実行されます
- **実行したコマンドをそのままワークフローに**: コマンドパレットの履歴行で **Ctrl+Enter**、完了したコマンドブロックのツールバーの ⚡、ターミナルの右クリック(ブロックの上)の「ワークフローとして保存」から、そのコマンドを本文に入れた状態で登録画面が開きます。名前は先頭の数語が仮に入るので、付け直して保存してください
- **プレースホルダの入力値を記憶**: `{{名前}}` の入力画面で前回の値が既定値として入ります(テンプレート側の既定値は、記憶が無い項目にだけ効きます)。入力画面の「入力した値を記憶する」を外して実行すると記憶を消します。値は `workflow-inputs.json` にこの PC だけで保存され、**設定の書き出しには含めません**(ホスト名やパス、場合によってはトークンのような、共有すべきでないものが入りうるため)。ワークフローを削除すると記憶も消えます
- 初回起動時にサンプルワークフローを登録

### タスク(package.json / Cargo.toml などの実行コマンド一覧)
- ヘッダー左の**「タスク」ボタン**で、ターミナルの**右横にペインとして開きます**。**いま表示しているシェルの作業ディレクトリ**にあるタスクランナー定義を読み取り、実行できるコマンドを一覧します
- ツールタブではなくペインなのは、タスクを押す目的が「実行して流れを見る」ことにあるためです。**一覧とターミナルが同時に見えている**ので、実行 → 出力の確認 → 次を実行、を画面の往復なしに続けられます。もう一度ボタンを押す(またはペイン右上の ✕)と閉じ、ターミナルが幅を取り戻します
- **幅は境界のドラッグで変えられます**(ペイン分割のスプリッターと同じ操作)。200〜640px の範囲で、ターミナル側にも最低幅を残すので、どちらかが潰れることはありません。ウィンドウを狭めるとペインが譲り、広げると**ドラッグした幅まで戻ります**(狭めた拍子に指定が失われない)
- 作業ディレクトリはシェル統合の **OSC 7** で受け取ります。`cd` するたび自動で読み直されるので、リポジトリを移動すればそのリポジトリのタスクが並びます
- 対応するファイル(定義ファイルごとに 1 枚のカード。同じ名前でも別物になりうるため、どのファイル由来かを必ず表示します):

  | ファイル | 実行コマンド |
  | --- | --- |
  | `package.json` | `npm` / `pnpm` / `yarn` / `bun` の `run <script>` |
  | `deno.json(c)` | `deno task <name>` |
  | `Cargo.toml` | `cargo build` / `test` / `check` / `clippy` / `fmt`、`run`(バイナリがある場合)、`--example` |
  | `pyproject.toml` | `uv` / `poetry` / `pdm` の同期・インストールとスクリプト |
  | `Makefile` | `make <target>`(`## コメント` を説明として拾います) |
  | `justfile` | `just <recipe>` |
  | `Taskfile.yml` | `task <name>` |
  | `composer.json` | `composer run <script>` |
  | `go.mod` | `go build ./...` / `go test ./...` / `go run .` / `go mod tidy` |
  | `compose.yaml` / `docker-compose.yml` | `docker compose up -d` / `down` / `build` / `ps` / `logs -f`、サービスごとの `up -d <name>` |
  | `Dockerfile` | `docker build -t <ディレクトリ名> .`、名前付きステージごとの `--target`、`docker run --rm -it <タグ>` |

- **Compose は V2 (`docker compose`) を使います**。V1 の `docker-compose` は 2023 年に EOL となり、現在の Docker には同梱されていません(ファイル名が `docker-compose.yml` のままでも構いません)。`services:` のキーだけを読み、`volumes:` など同じ形の別マッピングは対象外です
- **Dockerfile のタグはディレクトリ名から作ります**。Docker のイメージ名は小文字で `[a-z0-9]+([._-][a-z0-9]+)*` である必要があるため、`My Web App` は `my-web-app` に畳みます。使える文字が残らない場合は `-t` を付けず、タグ無しでビルドします。`FROM x AS y` の名前付きステージは、2 つ以上あるときだけ `--target` として並べます(`FROM alpine AS ${BASE}` のようなビルド引数は、展開できないので出しません)
- **パッケージマネージャの判定**は、リポジトリが実際に使っているものに合わせます。`package.json` の `packageManager` フィールドが最優先で、無ければロックファイル(`bun.lock` / `pnpm-lock.yaml` / `yarn.lock` / `package-lock.json`)、それも無ければ `npm` です
- 「実行」ボタンでフォーカス中のペインにそのコマンドを送って実行します(**Shift+クリックで実行せず入力するだけ**)。アプリ側が直接プロセスを起動することはありません — あくまでユーザーが打ったのと同じようにシェルへ入力するので、エイリアスや環境変数、確認プロンプトはそのまま効きます
- コマンドパレットからも `タスク: <名前>` として検索・実行できます(ペインの開閉も「タスク一覧を開く / 閉じる」として並びます)。ツールパネルを開いたまま実行した場合は、出力が見えるようシェル表示へ戻ります
- **SSH スレッドは未対応**です(作業ディレクトリを知るにはリモート側のシェル統合が必要で、まだ入れていません)。その旨をペインに表示します

### 組み込みサーバー(ホットリロード付き)
- ヘッダー「サーバー」タブで、**任意のディレクトリをそのまま HTTP で公開**できます。ビルド済みサイト・カバレッジレポート・ドキュメントの確認に、`python3 -m http.server` や `npx serve` を別のターミナルで占有しておく必要がなくなります
- **パッケージ管理ディレクトリは監視しません**: `node_modules` / `vendor` / `target` / `Pods` / `venv` / `__pycache__` / `bower_components` と、**ドットで始まる全ディレクトリ**(`.git` / `.venv` / `.yarn` / `.next` / `.gradle` など)には**監視を張らず、そもそも降りません**。これらは install やビルドのたびに大量に変化するうえ、再帰的に監視すると OS の監視上限(Linux の `fs.inotify.max_user_watches`)を使い切り、**ツリー全体のホットリロードが止まります**。このリポジトリで実測したところ、全 2,166 ディレクトリが **24** になりました(`target/` だけで 2,046)。**配信には影響しません** — ページが `/node_modules/x/x.js` を要求すれば従来どおり返します
- **ホットリロード**: 公開中のディレクトリを監視し、ファイルが変わるとブラウザが自動でリロードします。仕組みは HTML に小さな `<script>` を挿入し、[SSE](https://developer.mozilla.org/docs/Web/API/Server-sent_events) (`/__senju__/reload`) で更新を push するだけです。**ファイルは書き換えません** — 挿入は配信時のレスポンスに対してのみ行われます
- **ポート**: 指定したポートで待ち受けます。**0 を指定すると空きポートを自動で割り当て**、実際のポートを表示します。既に使われているポートを指定した場合は、起動ボタンを押したその場でエラーになります(裏で静かに失敗することはありません)
- **「現在地」ボタン**: いま表示しているシェルの作業ディレクトリ(OSC 7 で受け取ったもの)をそのまま公開先に入れます
- **公開するディレクトリには `index.html` を置いてください**。ディレクトリ一覧を出さない設計のため、`index.html` の無いディレクトリは 404 になります(その中のファイルは、パスを直接指定すれば配信されます)
- **SPA モード**: どのファイルにも一致しないパスに `index.html` を返します。クライアントサイドルーティング用。既定はオフです(オンにすると、打ち間違いも実際に消えているアセットも 200 になり気付けなくなるため)
- **保存した設定**: よく使う公開設定(名前・ディレクトリ・ポート・オプション)を保存して、一覧やコマンドパレットから 1 クリックで起動できます。保存されるのは**設定だけ**で、起動状態は保存されません
- **アクセスログ**: 直近のリクエストをメソッド・パス・ステータス付きで表示します(4xx / 5xx は色を変えて表示)

#### セキュリティ上の設計
プレビュー用のサーバーは「ディレクトリの中身を、聞いてきた相手に渡すプログラム」なので、次の 3 点は設定で変更できません。

- **待ち受けは 127.0.0.1 のみ**です。`0.0.0.0` にする UI はありません。作業ディレクトリをカフェや社内 LAN に公開してしまうのは、うっかり起きてよいことではないためです
- **公開ルートの外には出られません**。パスは復号してから `..` や Windows のパス片(`C:` や `\`)を拒否し、さらにディスク上で解決した結果がルート配下であることを確認します。したがって**ツリー外を指すシンボリックリンクも配信されません**
- **ドットファイルは配信しません**。プロジェクトディレクトリは `.env` や `.git/config` が置かれている場所そのものであり、それらはプレビュー対象ではないためです
- **ディレクトリ一覧は表示しません**。ディレクトリはその `index.html` 経由でのみ到達でき、無い場合は **404**(存在しないパスとまったく同じ応答)になります。一覧はポートに到達できる相手に作業ディレクトリの中身を丸ごと列挙させるもので、「相手が既に知っているファイルを 1 つ返す」のとは開示の規模が違うためです。末尾スラッシュを補う 301 リダイレクトも、**index がある場合にしか返しません** — でないとリダイレクト自体がディレクトリの存在を教えてしまいます

#### 意図的に持たない機能
HTTPS、キープアライブ(応答ごとに接続を閉じます)、`Range` リクエスト(**`<video>` のシークは動きません**)、圧縮、HTTP/2 はありません。いずれも本番サーバーには必要なものですが、**これを本番サーバーと取り違えてはいけない**ためです。

### 起動セット(いつも開くシェル+ワークフローの一括初期化)
- ヘッダー「起動セット」タブで登録・管理。名前と、上から順に開く「項目」のリストを持ちます
- 各項目は **ローカルプロファイル または SSH ホスト** のどちらかを開き、任意で **ワークフローを自動実行**(実行モード)します
- 「起動」を押すと、登録順に 1 つずつスレッドを作成し(SSH 項目でパスワードが必要な場合はその場でプロンプトが出ます — パスワードは保存されないため自動化できません)、各スレッドの準備ができ次第そのワークフローを実行します
- プロファイル/ホストが削除済みの項目や、SSH 接続をキャンセルした項目はスキップされ、別のスレッドに誤ってワークフローが実行されることはありません
- 新規スレッドの ▾ メニューとコマンドパレットからも直接起動できます

### SSH 接続管理
- ホスト(名前 / ホスト / ポート / ユーザー / 認証方式)を登録・管理
- **グループ・タグ・色ラベル**: ホスト編集画面の「ラベル」で、ワークフローと同じ `/` 区切りの階層グループ(例: `Prod/Web`)、カンマ区切りのタグ、6 色の色ラベル(赤 / 橙 / 黄 / 緑 / 青 / 紫)を付けられます。SSH パネルはグループごとに見出しを付けて並び、検索はグループ名とタグにも効きます。**色はカード・スレッド一覧・新規スレッドメニューに付き、接続中はそのペインが同じ色で縁取られる**ので、本番機を赤にしておけば打つ前に気づけます。ラベルは設定の書き出しにも含まれます(資格情報と違い、秘密ではないため)
- **ホスト鍵 (known_hosts) の管理**: SSH パネルの「ホスト鍵」で `~/.ssh/known_hosts` の記録(ホスト / 鍵種別 / SHA256 フィンガープリント / 行番号。ハッシュ化されたホスト名や `@cert-authority` 等のマーカーも表示)を一覧し、選んだ行を削除できます。削除は該当行だけを取り除き、コメント・空行・他の行はバイト単位でそのまま残します(書き込みは一時ファイル → rename で、途中で落ちても known_hosts が空になりません)。**接続時に鍵の不一致で拒否された場合**は、不一致になった行番号と新しいフィンガープリントを示したうえで「記録を削除して接続し直す」を提案します(既定はキャンセル。削除後の接続は初回扱いになり、新しい鍵の確認が出ます)。鍵が変わった理由に心当たりが無ければ削除しないでください
- **鍵ペアの生成**: 「鍵ペアを生成」で Ed25519 の鍵ペアを `~/.ssh/<名前>`(OpenSSH 形式・0600)と `<名前>.pub` に作ります。パスフレーズは任意で、暗号化にだけ使い保存しません。既存のファイルは上書きしません。生成後に公開鍵をコピーできます
- **公開鍵の配置 (`ssh-copy-id` 相当)**: ホストカードの「公開鍵を配置」で、**接続中のセッションの SFTP** を使ってリモートの `~/.ssh/authorized_keys` に公開鍵を追記します(`~/.ssh` を 0700、`authorized_keys` を 0600 に揃えます)。同じ鍵(鍵種別と鍵本体で比較。コメントや `no-pty,from=…` のオプション接頭辞は無視)が既にあれば何もしません。配置後にそのホストの認証方式を秘密鍵へ切り替えるチェックが付いているので、パスワードで一度入ってから鍵認証に移行できます
- **自動再接続(ホストごとのオプトイン)**: ホスト編集画面の「再接続 > 接続が切れたら自動で再接続する」をオンにすると、回線断などで**セッションが途中で切れた**とき(バックエンドが終了コード -1 を報告したとき)に、**同じスレッドのまま**(スクロールバック・ペイン・色ラベル・ログはそのまま)2・4・8・16・30 秒の間隔で最大 5 回つなぎ直します。`exit` で正常終了したときと、アプリ起動時のセッション復元は対象外です(後者の方針は変わりません)。保存済みの資格情報があればそれを使い、無ければ認証に失敗した最初の再試行で 1 回だけ入力を求めます(キャンセルで中止)。ホスト鍵の問題(未知・不一致)があれば自動では続けず、手動接続に委ねます。再接続中は入力を受け付けず、スレッド一覧に ⟳ が付きます。スレッドを閉じれば再試行も止まります
- **グループ単位の一斉接続・一斉実行**: グループ見出しの「すべて接続」で、そのグループ(サブグループを含む)の未接続ホストへ順に接続します(接続済みはスキップ。パスワードや初回のホスト鍵確認は 1 台ずつ出ます)。「一斉実行…」はコマンドを 1 つ入力して、**接続中のホスト全部に同じコマンドを送ります**。送信先はチェックリストで外せます。未接続のホストは一覧に出ますが送信先にはなりません — 一斉実行の途中で勝手に接続・認証を始めるより、先に「すべて接続」してもらうほうが安全なためです
- **`~/.ssh/config` からの取り込み**: SSH パネルの「~/.ssh/config を取り込み」で、既存の `Host` エントリ(`HostName` / `User` / `Port` / `IdentityFile`)を候補一覧から選んで一括登録できます。登録済み(ホスト+ポート+ユーザーが一致)の候補は「(登録済み)」と表示され既定で除外。`User` の無いエントリは ssh と同様にローカルのログイン名を補います(ワイルドカードの `Host` パターン・`Match`・`Include` は対象外)
- 認証方式: パスワード / 秘密鍵ファイル(パスフレーズ対応)/ ssh-agent / **秘密鍵 + パスワード併用**(`AuthenticationMethods publickey,password` のような多段認証。公開鍵で認証後、サーバが要求すればパスワードで認証を完了)
- **保存前に「接続テスト」**: ホスト編集画面から、到達性・認証・ホスト鍵(SHA256 フィンガープリント)を保存前に確認できます。テスト用パスワード / パスフレーズは保存されず、テストではホスト鍵を `known_hosts` に記録しません
- **パスワード・パスフレーズは既定では保存されません**(接続時に入力し、その接続にのみ使用)
- **保存したい場合は明示的にオン(ホストごとの任意設定)**: ホスト編集画面の「パスワード / パスフレーズを保存する」をオンにすると、**接続が成功したときだけ**入力内容を設定ディレクトリの `ssh-hosts.json` に保存し、次回以降は入力を省略します。**既定はオフ**です。チェックを外す、またはホストを削除すると保存済みの内容も削除します。保存済みの値がフロントエンド(WebView)に渡ることはありません — アプリ側が受け取るのは「保存済みかどうか」の真偽値だけです
- **保存先は平文のファイルです。** 設定を書き出して別マシンへ移せるようにするため、OS のキーチェーンは使いません(その代わり[設定の書き出し](#設定の書き出し--取り込み)には資格情報を含めません)。この PC の設定ディレクトリを読める人は読めるので、オンにするかどうかはその前提でご判断ください
- 接続はタブとして開き、リサイズ・keepalive(30 秒)に対応
- **OpenSSH 互換の known_hosts 検証(TOFU)**: `~/.ssh/known_hosts` と照合し、記録された鍵と異なる鍵を検知した場合は MITM の可能性があるとして常に接続を拒否します。未知のホストへの初回接続時は、鍵種別と SHA256 フィンガープリントを表示する確認ダイアログが出て、承認すると鍵を `known_hosts` に保存した上で接続します
- **ポートフォワード(`ssh -L` / `-R` / `-D` 相当)**: ホスト編集画面の「ポートフォワード」に 1 行 1 件で登録すると、そのホストへの接続時に自動で開始し、切断で停止します。開始・失敗はターミナルにバナー表示され、不正な書式と**ローカルポートの重複**は保存時に検出します

  | 種別 | 書式 | 例 |
  | --- | --- | --- |
  | ローカル (`-L`) | `ローカルポート:リモートホスト:リモートポート` | `8080:localhost:80` |
  | リモート (`-R`) | `-R リモートポート:ローカルホスト:ローカルポート` | `-R 9000:localhost:3000` |
  | 動的 (`-D`) | `-D ローカルポート` | `-D 1080` |

  接頭辞は `-L` / `L` のどちらでも書けます(大文字小文字は区別しません)。**接頭辞を省いた行は `-L`** として扱うため、以前のバージョンで保存した設定はそのまま動きます

  **リスナーは必ずループバックに限定されます** — `-L` / `-D` はこの PC の `127.0.0.1`、`-R` は**サーバー側の** `127.0.0.1` にバインドします(OpenSSH の `GatewayPorts no` と同じ既定)。LAN へ公開する設定は用意していません

  `-R` では、サーバーが要求したポートを開けなかった場合はその旨をバナー表示し、セッション自体は続行します。またサーバーから届いた転送チャネルは**こちらが要求したポートに一致するものだけ**を受け付けます(要求していないポートのチャネルは接続せずに破棄)

  `-D` は認証なしの SOCKS5(CONNECT のみ)です。ループバック限定のため認証なしで問題ありませんが、BIND / UDP ASSOCIATE は受け付けません。**ホスト名の解決は SSH サーバー側で行われます**(手元の DNS に問い合わせないので、内部ホスト名が漏れません)
- **多段接続(踏み台 / ProxyJump, `ssh -J` 相当)**: ホスト編集画面の「多段接続」で、登録済みの SSH ホストを踏み台として接続順に選ぶと、それらを経由して目的ホストへ接続します。各段は前段の上に開いた `127.0.0.1` の direct-tcpip トンネルを通って接続する入れ子トンネル方式で、**ホスト鍵は段ごとに検証**します(未知の鍵は段ごとに TOFU 確認、記録済みと異なる鍵は常に拒否)。認証情報は接続時に**段ごと**に入力し、保存されません。ポートフォワードは目的ホスト側で動作します

### ファイル転送(SFTP)
- コマンドパレットの「ファイルをアップロード (SFTP)」/「ファイルをダウンロード (SFTP)」から、**いま開いている SSH スレッドの接続をそのまま使って**ファイルを送受信します。再認証は不要で、ホスト鍵を別途信頼する必要もなく、多段接続(ProxyJump)の場合はその**終端のホスト**が相手になります
- アップロードはローカルのファイルを OS のファイル選択で選び、リモートのパスを入力します。ダウンロードはリモートのパスを入力し、保存先を OS の保存ダイアログで選びます
- リモートのパスは**サーバー側で解決**されるため、`~/dumps/db.sql` や相対パス(ログイン時のホーム基準)がそのまま使えます。転送後は解決後の実際のパスを通知に表示します
- 進捗バーと**中止**に対応。転送は 32KB ごとのストリーミングで、ファイル全体をメモリに読み込みません(データベースのダンプやコアファイルを扱う前提)。中止した場合は**エラーとして扱います** — 転送先には途中までのファイルが残るため、成功として扱うと壊れたファイルが完成品に見えてしまうからです
- サイズが取得できないサーバーでは進捗バーは不確定表示になり、転送済みバイト数だけを表示します
- **ドラッグ&ドロップでアップロード**: OS のファイル / フォルダを **SSH スレッドのペインへドロップ**すると、送り先ディレクトリの確認ダイアログを経てアップロードします(複数可、1 件ずつ順に転送。フォルダはその名前でリモートに再作成し、既存のディレクトリは再利用、同名ファイルは上書き。途中で失敗すれば残りは送りません)。送り先の既定は、シェルが OSC 7 で作業ディレクトリを通知していればそのディレクトリ、そうでなければ SFTP のログインディレクトリ(通常はホーム)です。**ローカルシェルのペインへドロップ**した場合は転送ではなく、シェル用に引用符付けしたパスを入力欄に貼り付けます
- **右クリックメニュー**: SSH スレッドのターミナルを右クリックすると「ファイル転送 (SFTP)」に「ファイルをアップロード…」「フォルダをアップロード…」「リモートファイルを開く…」が出ます(ファイル選択ダイアログ / リモートファイルブラウザ。送り先・開始位置は上と同じ既定)
- **リモートファイルブラウザ**: コマンドパレットの「リモートファイル (SFTP)」で、サーバー側のディレクトリを辿れます。ディレクトリをクリックで移動、ファイルをクリックでダウンロード、「ここにアップロード」で表示中のディレクトリへ送信します
  - 表示は**サーバーが解決した絶対パス**を基準に移動するので、`~` や `..` が表示パスに積み上がりません。ルートに達すると「上へ」は消えます
  - 並び順はディレクトリ優先・名前順(大文字小文字を無視)です。サーバーはファイルシステムが返した順のまま渡してくるため、件数の多いディレクトリでは実質ランダムで、そのままでは探せません
  - シンボリックリンクは名前の後ろに `→` を付けて示します。ディレクトリかどうかはリンク先で判定します
  - **参照と転送のみで、削除・リネーム・ディレクトリ作成はできません。** 他人のサーバー上の破壊的操作は専用の確認設計が要るもので、「ファイルを失いうるブラウザ」は「まだディレクトリを作れないブラウザ」より悪いためです

### ウィンドウサイズ・位置の記憶
- 直前の終了時点のウィンドウサイズ・位置(最大化状態を含む)を記憶し、次回起動時に復元します(他の設定と同じくアプリ設定ディレクトリの JSON `window-state.json` に保存。プラグイン依存を減らすため `tauri-plugin-window-state` は使わず自前実装)

### セッション復元(前回のスレッド構成)
- 起動時に、前回開いていた**ローカルスレッドの構成(プロファイルと順序)**を自動で再作成します(既定オン。設定「起動 > 前回のスレッド構成を復元」で切替)
- SSH スレッドは認証が必要なため**自動再接続しません**。スキップした件数を起動時に通知し、SSH パネルや新規メニューから選んで接続します(パスワード等を保存しない方針のままです)
- レイアウトはスレッドの作成・終了のたびに `session.json` へ保存されます。プロファイルが削除されていた項目は既定プロファイルで開きます

### セッションログ(作業の記録)
- ターミナルに流れた内容を**セッション単位でファイルに残します**。Tera Term のログのように、何を打って何が返ったかのエビデンスとして使えます
- **SSH はホストごとのオプトイン**: ホスト編集画面の「セッションログ > このホストへのセッションを記録する」をオンにしたホストだけが対象です(既定オフ。root シェルの写しを黙ってディスクに残さないため)。ローカルシェルは設定「セッションログ > ローカルシェルも記録する」で全体のオン/オフ
- 保存先は設定「セッションログ」のフォルダ(空欄 = アプリの設定ディレクトリ内 `logs/`。`~` 展開可)。**日付ごとのサブフォルダ**に `<ホスト名>_<HHMMSS>.log` として保存し、同じ秒に同じホストへ 2 本開いた場合は `_2` を付けて分けます。先頭 1 行にホスト名と開始時刻のヘッダーが入ります
- **既定ではエスケープシーケンスを除いた読めるテキスト**で保存します(色・カーソル制御・OSC を除去、`\r\n` と単独の `\r` は `\n` に正規化、UTF-8 はそのまま)。設定でオフにすると生のバイト列をそのまま残します(`cat` で端末に流すと再現できます)
- 記録中のスレッドにはスレッド一覧に **●** が付き、ツールチップにファイルパスが出ます。ログを開けなかった場合(保存先が書き込めない等)は**セッションはそのまま続行し、記録なしで続ける旨を通知**します
- 書き込みはユーザー空間でバッファせず都度 OS へ渡すので、アプリが落ちても失われるのは OS が未書き込みの分だけです。保存先の変更は**次に開くセッションから**効き、開いているログは最後までその場所に書きます

### コマンドパレット
- `Ctrl+Shift+P` で起動。ワークフロー・SSH ホスト・アクション・**コマンド履歴**を横断ファジー検索
- `Enter` で実行、`Shift+Enter` で挿入のみ

#### パレットのキーを変更する(`palette_keys`)

`settings.json`(アプリ設定ディレクトリ)に `palette_keys` を書くと、パレットのキーを変えられます。書いていない(または空配列の)操作は既定のキーのままです。

```json
{
  "palette_keys": {
    "open": ["ctrl+space", "f1"],
    "next": ["arrowdown", "ctrl+j"],
    "prev": ["arrowup", "ctrl+k"],
    "save": ["ctrl+enter"]
  }
}
```

| 操作 | 内容 | 既定 |
|---|---|---|
| `open` | パレットを開く / 閉じる | `mod+shift+p`(macOS は `⌘⇧P`、それ以外は `Ctrl+Shift+P`) |
| `next` / `prev` | 選択を下 / 上へ | `arrowdown`, `ctrl+n` / `arrowup`, `ctrl+p` |
| `run` | 実行 | `enter` |
| `insert` | 入力欄に挿入のみ | `shift+enter` |
| `save` | ワークフローとして保存 | `ctrl+enter`, `meta+enter` |
| `close` | 閉じる | `escape` |

- **書式**: 修飾キーと 1 つのキーを `+` でつなぎます(大文字小文字は区別しません)。修飾キーは `ctrl` / `alt` / `shift` / `meta`(別名: `control`, `option`・`opt`, `cmd`・`command`・`super`・`win`)。`mod` は macOS では `meta`(⌘)、それ以外では `ctrl` です。キー名は `KeyboardEvent.key` を小文字にしたもの(`a`, `/`, `enter`, `escape`, `arrowdown`, `space`, `tab`, `f1` など。別名: `esc`, `return`, `up`/`down`/`left`/`right`, `spacebar`)です。Shift で変わるキーは「キーボードが実際に出す文字」で書きます(US 配列の `?` なら `ctrl+shift+?`)。`+` そのものはキーに使えません
- `open` は誤って打鍵のたびにパレットが開かないよう、`ctrl` / `alt` / `meta` のいずれかを含むか、`f1`〜`f24` である必要があります
- `open` を変更すると、既定の `Ctrl+Shift+P` と「ターミナル外での `Ctrl+P`(`⌘P`)」でのパレット起動は無効になります(`Ctrl+P` による印刷ダイアログの抑止は変わりません)
- パレットを開くキーは、他のアプリのショートカット(`Ctrl+Shift+T` など)より優先されます。ワークフローのショートカットにも同じキーは割り当てられません
- 解釈できない操作名・キーは無視され、起動時や再読み込み時に警告が出ます
- 変更は、コマンドパレットの「**設定ファイルを再読み込み**」か、アプリの再起動で反映されます(「設定ファイルをフォルダーで表示」で `settings.json` の場所を開けます)。設定画面の「保存」は読み込み済みの内容を書き戻すため、アプリを開いたまま `settings.json` を編集したときは、先に再読み込みしてください

### 永続コマンド履歴(スレッド横断)
- コマンドブロック(OSC 133)が完了するたびに、実行したコマンドを `history.json` に保存します。**ローカルでも SSH でも**マーカーを発行するシェルなら記録されます
- コマンドパレットから横断検索し、`Enter` でアクティブなスレッドで再実行、`Shift+Enter` で入力欄に挿入、**`Ctrl+Enter` でワークフローとして保存**(本文を入れた登録画面が開きます)
- **メタデータ付き**: 各コマンドに、実行したホスト(SSH ホスト名 / ローカルプロファイル名)・終了コード・所要時間・実行回数を記録し、パレットの行に `SSH prod-web · ✗ 1 · 12s · ×3 · 9/18 14:02` のように表示します
- **絞り込みトークン**: パレットの検索欄に `@ホスト名`(ホストで絞り込み)、`!failed` / `!ok`(失敗 / 成功したものだけ)、`#ssh` / `#local`(実行場所)を混ぜられます。例: `@prod !failed deploy`。絞り込み中は履歴だけが表示されます
- 同一コマンドは最新の 1 件に集約され(実行回数は加算)、最大 2,000 件で打ち切り。コマンド文字列はプロンプト行から抽出するヒューリスティックです(プロンプト末尾 `$ ` / `❯ ` / `# ` / `% ` / `> ` 以降を採用)

### AI コマンド支援(プライバシー第一・自分の API キー)
- コマンドパレットの「**AI にコマンドを聞く**」で、やりたいことを自然言語で説明すると、環境(OS・シェル)に合わせたシェルコマンドを提案します
- **設定「AI コマンド支援」に自分の Anthropic API キーを登録した場合のみ有効**(空欄なら機能は完全に無効)。API 呼び出しはアプリから Anthropic API へ直接行われ、第三者のサーバーは経由しません
- **送信されるのは入力した質問と OS/シェル名のみ**。ターミナルの表示内容・コマンド履歴・ファイルは送信されません
- 提案されたコマンドは**自動実行されません**。編集可能な形で表示され、「ターミナルへ挿入」で入力欄にタイプされるだけです(実行は自分で Enter)。破壊的な操作には注意書きが付きます
- モデルは既定で `claude-opus-5`(設定で変更可能)。**API キーは `settings.json` に平文で保存**されます(設定の書き出しには含まれません)。設定画面のキー欄は空欄のまま「保存済み」と表示され、空欄で保存すると既存のキーはそのまま維持されます(削除は「保存済みのキーを削除する」から)。キーの値が WebView に渡ることはありません

### 自動アップデート(配布経路ごとに管理を分離)
- 起動時に GitHub Releases の署名付きアップデートをサイレント確認し、新しいバージョンがある時だけ通知します(適用・再起動は毎回確認)。コマンドパレットの「アップデートを確認」で手動確認も可能
- 設定「起動 > 起動時にアップデートを確認」でオフにできます。署名検証は tauri-plugin-updater が強制します
- **入手経路ごとに更新の担当者が変わります**。アプリは起動時に自分がどう入ったかを判定し、担当者が別にいる場合は自分では更新しません:
  - ダウンロードした `.exe`(NSIS)/ `.msi` / `.dmg` / `.AppImage` → アプリ内アップデータ(**入れたのと同じ形式**にのみ更新)
  - Microsoft Store → Store が更新(アプリ内アップデータは**プラグインごと無効化**し、Store の更新画面を開く導線を出します)
  - `.deb` / `.rpm` / Homebrew → apt / dnf / brew が更新(理由を表示)
  - 開発ビルド → 何もしません
- 配信の有効化にはオーナーの署名鍵設定が必要です(手順: [リリース・自動アップデート・配布ガイド](../../.docs/release-and-distribution.md))。未設定のビルドではチェックは静かに何もしません

### Microsoft Store 配布(MSIX)
- Store は NSIS/MSI インストーラを受け付けないため、同じバイナリから MSIX を別途パッケージします(`scripts/build-msix.ps1` / `src-tauri/msstore/`)
- CI は Store の識別情報(リポジトリ変数 `MSSTORE_IDENTITY_NAME` ほか)が設定されている時だけ MSIX を生成し、`v*` タグではドラフトリリースにも添付します。詳細は[配布ガイド §4](../../.docs/release-and-distribution.md)

### 設定の書き出し / 取り込み

- 設定画面の「設定の書き出し / 取り込み」から、**設定・ワークフロー・SSH ホスト・端末プロファイル・起動セット・サーバー設定**を 1 つの JSON にまとめて書き出せます。別マシンへの移行やバックアップ、Git での管理を想定しています
- **資格情報は含まれません**。API キーと SSH の保存済みパスワード / パスフレーズは書き出し時に除外され、`save_credentials` も `false` になります(保存済みだと表示されるのに中身が無い、という状態を避けるため)。移行先では入力し直しになりますが、そのぶん**書き出したファイルは共有・コミット・バックアップできます**
- 手で編集したファイルや将来の版が資格情報を混ぜてきても、**取り込み側でもう一度除去**します。この形式の約束をファイルの中身に委ねないためです
- 取り込みは **id 単位の上書き**です。同じファイルを 2 回取り込んでも増えず、移行先にだけあるホストやワークフローも消えません。ワークフロー単体の書き出し(id を捨ててチーム共有する用途)とは別物で、こちらは id を保持します — **起動セットはプロファイルを id で、多段接続はホストを id で参照している**ためです
- 取り込む前に、そのファイルに何が入っているか(各件数と、アプリ設定を上書きするかどうか)を確認するダイアログが出ます

### 多言語対応(日本語 / English)
- 設定の「外観 > 言語」で **日本語 / English** を切り替えられます。UI 全体(タブ・パネル・ボタン・メニュー・モーダル・トースト・ショートカット一覧・ツールチップ)が即時に切り替わります
- ユーザーが入力したデータ(ワークフロー名・グループ名・タグ・ホスト名など)はそのまま保持されます(翻訳対象は UI の文言のみ)
- 文言は `ui/app.js` の `STRINGS` に日本語 / 英語のペアで一元管理し、静的な HTML は `data-i18n` 属性、動的な文字列は `tr()` で解決します。設定は他の設定と同様に JSON へ保存されます(既定は日本語)

## キーボードショートカット

修飾キーは OS に合わせて変わります。以下の表の **`Mod`** は **Windows / Linux では `Ctrl`、macOS では `⌘`** です。

| キー | 動作 |
| --- | --- |
| `Mod+Shift+P` | コマンドパレット(キーは `settings.json` の `palette_keys` で変更可。ターミナル外にフォーカスがある時は `Mod+P` でも開けます。ターミナル内の `Ctrl+P` はシェルの「前のコマンド」としてそのまま渡されます)|
| `Mod+Shift+T` | 新しいローカルスレッド |
| `Mod+Shift+W` | フォーカス中のスレッドを終了 |
| `Mod+Shift+D` | ペインの上下分割 / 分割解除 |
| `Mod+Shift+E` | ペインの左右分割 / 分割解除 |
| `Mod+Shift+B` | 入力ブロードキャスト(全ペインへ送信)の切替 |
| `Ctrl+Shift+C` / `V`(macOS は `⌘C` / `⌘V`) | 選択範囲をコピー / クリップボードから貼り付け |
| `Mod+Shift+F` | ターミナル内検索 |
| `Mod+Shift+↑` / `↓` | 上 / 下のペインへフォーカス移動(左右分割時は左 / 右)|
| `Mod+Shift+/` | キーボードショートカット一覧 |
| `Ctrl+Alt+↑` / `↓` | 前 / 次のコマンドブロックへ(要シェル統合) |

- シェル側の `Ctrl+K` などのキーバインドを潰さないよう、Windows / Linux のアプリショートカットは `Ctrl+Shift` / `Ctrl+Alt` 系にしています
- **macOS では `Ctrl` をアプリのショートカットに使いません**。`Ctrl+C`(SIGINT)・`Ctrl+D`(EOF)・`Ctrl+R`(履歴検索)などはターミナルに届くべきキーなので、アプリ側は `⌘` だけを使います。コピー / ペーストも macOS の慣習どおり `⌘C` / `⌘V` です

## ビルド方法

前提: [Rust](https://rustup.rs/) と、Linux の場合は Tauri のシステム依存パッケージ。

```bash
# Linux (Debian/Ubuntu) のみ必要
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev

# 開発実行
cargo install tauri-cli --version "^2"
cargo tauri dev

# 配布用ビルド (Windows: .msi/.exe, macOS: .dmg/.app, Linux: .deb/.rpm/.AppImage)
cargo tauri build
```

フロントエンドはバンドラ不要の静的ファイル(`ui/`)で、xterm.js は `ui/vendor/` にベンダリング済みです。npm は不要です。

GitHub Actions(`.github/workflows/build.yml`)で 3 OS のビルドを自動実行します。`v*` タグを push するとドラフトリリースに各 OS のインストーラが添付されます。

**このワークフローはビルドアーティファクトを一切残しません。** タグ・PR・main への push のいずれでも、ビルドは実行しますが `upload-artifact` は使いません。3 OS 分のインストーラ(AppImage や dmg は数百 MB)を既定の 90 日保持するとアカウントのアーティファクト保存枠を使い切り、**ビルド自体は成功しているのにアップロードだけが失敗してジョブが赤くなる**ためです。

参照している処理も無いので、失うものはありません。`v*` タグでは tauri-action がインストーラを、別ステップが MSIX をドラフトリリースへ添付するので**リリースには一式が揃います**。`release-manifest` はそのリリースを `gh release download` で読んでおり、`download-artifact` を呼ぶステップはどこにもありません。タグ以外のビルドでは、成果物はそもそも誰も使いません。

> タグ以外のビルドを誰かに渡したい場合は、タグを打ち直すかリリースへ直接添付してください。`upload-artifact` ステップを復活させないでください(ワークフロー内にも同じ注意書きを残してあります)。

リリースの公開手順、自動アップデート(tauri-plugin-updater)の有効化、コード署名、winget / Homebrew での配布については [リリース・自動アップデート・配布ガイド](../../.docs/release-and-distribution.md) を参照してください(署名鍵や開発者アカウントなどオーナー側の準備が必要な項目をまとめています)。

## アーキテクチャ

```
crates/senju-core/   GUI 非依存のコア (cargo test でテスト可能)
  ├─ models.rs       Workflow / SshHost / Settings
  ├─ template.rs     {{placeholder}} の抽出・展開
  ├─ store.rs        JSON ファイル永続化 (アトミック書き込み)
  ├─ tasks.rs        package.json / Cargo.toml 等の解析 (タスク一覧)
  ├─ devserver.rs    組み込み静的サーバー + ホットリロード (127.0.0.1 のみ)
  └─ sessions/       セッション管理
      ├─ local.rs    portable-pty によるローカルシェル
      ├─ ssh.rs      russh による SSH シェル
      └─ sftp.rs     russh-sftp によるファイル転送(SSH セッション上の SFTP サブシステム)
src-tauri/           Tauri アプリ (コマンド定義・イベント転送)
ui/                  フロントエンド (xterm.js + vanilla JS)
```

- バックエンド → フロントエンドの出力は base64 で `session:data` イベントとして転送(マルチバイト文字が読み取り境界で分割されても壊れないようバイト列のまま渡し、xterm.js 側でデコード)
- 設定・ワークフロー・ホストはアプリ設定ディレクトリ配下の JSON(`workflows.json` / `ssh-hosts.json` / `settings.json` / `dev-servers.json`)。`settings.json` には設定画面にない項目(コマンドパレットのキー `palette_keys`)も手で書けます

## セキュリティ上の注意 / 既知の制限

- SSH ホストキーは OpenSSH 互換の `~/.ssh/known_hosts` で検証します(TOFU)。記録済みの鍵と異なる鍵を提示するホストへは、たとえ「信頼」操作をしていても常に接続を拒否します(MITM 対策)
- SSH のパスワード・パスフレーズは既定では永続化しません。ホストごとに明示的にオンにした場合のみ、`ssh-hosts.json` に**平文で**保存します
- **資格情報は平文でディスクに置かれます。** 設定を丸ごと書き出して別マシンへ移せるようにするため、OS のキーチェーンは使っていません。設定の書き出しからは除外するので書き出したファイルからは漏れませんが、**この PC の設定ディレクトリを読める人・プロセスからは読めます**。ディスク暗号化のない共用マシンでは、保存をオンにしない運用をおすすめします
- コマンドブロックは OSC 133 シェル統合が前提の軽量実装です(ステータスチップ+コピー+折りたたみ+ブロック間ジャンプ)。折りたたみは xterm.js の描画レイヤーへの視覚的なオーバーレイで、実際の行を削除・非表示にするものではありません
- 組み込みサーバーは 127.0.0.1 でのみ待ち受け、公開ルート外とドットファイルは配信しません(上記「セキュリティ上の設計」)。ファイル監視はパッケージ管理ディレクトリに降りません(下記)。それでもディレクトリ数が上限(4096)を超えるツリーでは、超過分が監視対象外になり、その旨を通知します(**サーバーは動いたまま、その範囲のファイルだけ自動リロードされません**)。監視を開始できなかった場合も、サーバーは動いたまま自動リロードのみ無効になります
- 組み込みサーバーの起動状態はプロセスと同じ寿命です。ウィンドウを閉じると全て停止します(ポートを掴んだまま操作できないサーバーが残らないようにするため)
- タスク一覧はシェル統合(OSC 7)が有効なローカルシェルでのみ機能します。定義ファイルは読み取るだけで実行はせず、1 MB を超えるファイルや壊れたファイルは黙って読み飛ばします(誤ったコマンドを出すより、出さないほうがましなため)。ディレクトリは再帰的に辿らず、作業ディレクトリ直下のみを見ます
- AI コマンド支援の API キーも `settings.json` に平文で保存します(同上)。キーの値が WebView に渡ることはありません(渡すのは「保存済みかどうか」だけ)
