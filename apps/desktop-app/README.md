# Senju Term

[Warp](https://github.com/warpdotdev/warp) にインスパイアされた、**カスタムコマンド(ワークフロー)管理**と **SSH 接続管理**を組み込んだクロスプラットフォームターミナルです。

- **実装言語**: Rust(バックエンド/コア)+ HTML/JS(描画は xterm.js)
- **対応 OS**: Windows / macOS / Linux(Tauri 2)
- ローカルシェルは [portable-pty](https://crates.io/crates/portable-pty)(Windows は ConPTY、Unix は openpty)
- SSH は [russh](https://crates.io/crates/russh)(Pure Rust。OpenSSL / libssh2 への依存なし)

## 主な機能

### ネイティブライクなカスタムタイトルバー
- **Windows / Linux**: OS 標準のウィンドウ枠(装飾)を無効化し、右上の最小化・最大化・閉じるをアプリ側で描画
- **macOS**: 装飾は残したままタイトルバーだけを透明化(`titleBarStyle: "Overlay"`)し、**OS 本物のトラフィックライト**をヘッダーに重ねて表示します。ヘッダーは左側を空けてボタンと重ならないようにしています(描画した偽のボタンは使いません)
- バー全体をドラッグでウィンドウ移動、ダブルクリックで最大化/復元
- 実行中のセッションがある状態で閉じようとすると確認します。macOS のトラフィックライトや `⌘W` など、アプリ側のボタン以外から閉じた場合も同じ確認が出ます
- **右クリックメニューの抑制**: テキスト入力欄(コピー&ペースト)とターミナル(ワークフロー起動メニュー)以外の場所 — ヘッダー・サイドバー・カードなど、実際に機能する項目が無い場所 — では、WebView 既定の右クリックメニュー(再読み込み/検証など)を表示しません
- **UI フォント**: アプリ全体(ターミナル本体を除く)の表示フォントは [Noto Sans](https://fonts.google.com/noto/specimen/Noto+Sans) / [Noto Sans JP](https://fonts.google.com/noto/specimen/Noto+Sans+JP) を `ui/vendor/fonts/` に同梱し自己ホスト。OS にフォントが入っていなくても、また CDN へアクセスできないオフライン環境でも同じ見た目になります(ターミナル本体のフォントは設定画面の「フォントファミリー」で別途指定する等幅フォントのままです)

### ターミナル / スレッド管理
- セッションを「スレッド」として左ペインで一覧管理(ローカルシェル / SSH が同居)。クリックで表示切替、非表示スレッドもバックグラウンドで動作し続けます
- **動的タイトル**: シェルが OSC タイトル(`\e]0;...\a`)を送ると、スレッド名が自動で追従します
- **スレッド名のリネーム**: スレッド項目をダブルクリックでインライン編集(Enter で確定 / Escape でキャンセル)。空欄で確定すると自動タイトルに戻ります。リネームすると自動タイトル追従は止まります
- **スレッドの固定(ピン留め)**: 📍 ボタンでスレッドを左ペイン上部に固定。固定中のスレッドは一覧の先頭に並び、誤って閉じないよう終了時に確認します
- **非表示スレッドのアクティビティ表示**: 表示していないスレッドに出力があると、一覧のタイトル横に teal の●が点灯します
- **ペイン分割 — 上下**(`Ctrl+Shift+D`)**/ 左右**(`Ctrl+Shift+E`): 各ペインのヘッダーにあるドロップダウン、または左ペインのスレッド一覧から、どのスレッドを表示するか個別に選択可能。同じスレッドを両ペインが取り合った場合は自動でスワップ。境界はドラッグでリサイズ。分割中に反対方向のショートカットを押すと、ペインを閉じずにその場で向きだけ切り替わります
- **入力ブロードキャスト(一斉入力)**(`Ctrl+Shift+B`): 分割中にオンにすると、キー入力・貼り付けが表示中の全ペインへ同時に送られます(複数サーバーへの同一コマンド実行などに)。オン中は各ペインのヘッダーにアクセントカラーのラインが表示され、分割を解除すると自動でオフになります。パレットやワークフローからの実行はフォーカス中のペインのみが対象です
- **コピー & 貼り付け**(`Ctrl+Shift+C` / `Ctrl+Shift+V`): 選択範囲をシステムクリップボードへコピー、クリップボードの内容をアクティブなスレッドへ貼り付け
- **ターミナル内検索**(`Ctrl+Shift+F`): xterm.js の addon-search でスクロールバックを含めて文字列検索。前へ / 次へ移動可能
- xterm.js による 256 色 / True Color 描画。フォントファミリー・スクロールバック行数(既定 10,000 行)は設定画面から変更可能
- **GPU レンダリング(WebGL)**: xterm の WebGL アドオンで描画を GPU 高速化(既定オン)。WebGL が使えない環境では自動で通常レンダラにフォールバックし、コンテキスト喪失時も安全に復帰します。設定「ターミナル > GPU レンダリング」でオフにでき、変更は開いているスレッドにも即時適用されます
- **ライト / ダークテーマ**: 設定画面の「外観 > テーマ」で切替。アプリ UI とターミナルの配色(ANSI カラー含む)が連動して切り替わります

### コマンドブロック(Warp 相当・シェル統合)
- シェルが [OSC 133](https://gitlab.freedesktop.org/Per_Bothner/specifications/blob/master/proposals/semantic-prompts.md) シーケンスを発行すると、コマンド単位の「ブロック」を認識します
- **終了ステータスチップ**: 実行を終えた各コマンドのプロンプト行の右端に ✓(成功)/ ✗ 終了コード(失敗)のバッジを表示
- **ブロックツールバー**: チップにマウスを重ねるとコピー・折りたたみボタンが表示されます
  - **コピー**: プロンプト行からそのコマンドの出力末尾までをまとめてクリップボードにコピー
  - **折りたたみ**: コマンド行は残したまま出力だけを畳んで隠す(再クリックで展開)。表示上のオーバーレイのみで、スクロールバックや検索の対象からは消えません
- **ブロック間ジャンプ**: `Ctrl+Alt+↑` / `Ctrl+Alt+↓` で前後のコマンドのプロンプト行へスクロール

#### シェル統合の自動有効化

ローカルシェルが **bash / zsh / fish** の場合、起動時に OSC 133 の連携フックを自動で組み込みます。ユーザーの `~/.bashrc` / `~/.zshrc` / `~/.config/fish/config.fish` は一切変更しません:

- **bash**: `--rcfile` で生成した一時 rcfile 経由(実行ファイル引数を明示的にカスタムしているプロファイルではスキップ)。中で `~/.bashrc` を先に source してから連携フックを追記します。「コマンド開始」マーカー(133;C)は bash 4.4 以降では `PS0`、それ以前(**macOS 同梱の bash 3.2 など**)では `DEBUG` トラップで発行します(既に `DEBUG` トラップが設定されている場合 — bash-preexec など — は上書きせず、そのままにします)
- **zsh**: `ZDOTDIR` を生成した一時ディレクトリへ向ける方式。`.zshenv` / `.zprofile` / `.zshrc` / `.zlogin` それぞれが実ホーム(または既存の `$ZDOTDIR`)の同名ファイルを source するプロキシになっており、ユーザーの設定は省略されません
- **fish**: `-C` (init-command) で connect — fish 自身の `config.fish` 読み込み後に追記実行されるだけなので、ファイル生成は不要です

設定画面の「ターミナル > シェル統合を自動で有効化」でオフにできます(既定は有効)。SSH 接続・カスタムプロファイル(bash/zsh/fish 以外の実行ファイル)には影響しません。

無効化した場合や、他のシェル/手動セットアップで OSC 133 を組み込みたい場合の設定例:

  **bash** (`~/.bashrc`, bash 4.4+):
  ```bash
  PS1='\[\e]133;A\a\]'"$PS1"'\[\e]133;B\a\]'
  PS0='\[\e]133;C\a\]'
  PROMPT_COMMAND='printf "\e]133;D;%s\a" "$?"'"${PROMPT_COMMAND:+;$PROMPT_COMMAND}"
  ```

  **zsh** (`~/.zshrc`):
  ```zsh
  precmd() { print -Pn '\e]133;D;%?\a\e]133;A\a' }
  preexec() { print -n '\e]133;C\a' }
  PS1="$PS1"$'%{\e]133;B\a%}'
  ```

  **fish** (`~/.config/fish/config.fish`):
  ```fish
  function __senju_blocks_prompt --on-event fish_prompt
      printf '\e]133;D;%s\a\e]133;A\a' $status
  end
  function __senju_blocks_preexec --on-event fish_preexec
      printf '\e]133;C\a'
  end
  ```

### ターミナルプロファイル(Windows Terminal 相当)
- 起動するシェルを「プロファイル」として登録・管理(名前 / 実行ファイル / 引数 / 作業ディレクトリ)
- 「＋ 新規」の **▾ メニューから起動するプロファイル、または登録済みの SSH 接続先を選択**(Windows Terminal のドロップダウン相当)。初回起動時に OS に応じた既定プロファイルを自動生成(Windows: PowerShell / コマンドプロンプト、Unix: bash / zsh / fish のうち存在するもの)
- **既定のプロファイルを設定可能**。「＋ 新規」ボタンやショートカットはこの既定プロファイルで起動します

### カスタムコマンド管理(Warp の Workflows 相当)
- コマンドテンプレートを名前・説明・タグ付きで登録/編集/削除/検索
- `{{名前}}` / `{{名前:既定値}}` 形式のプレースホルダに対応。実行時に入力ダイアログで値を埋めます
- 「実行」(Enter 送信つき)と「挿入」(入力欄に置くだけ)の 2 モード。複数行のコマンドテンプレートは「実行」時に行ごとに Enter を送信します(手で 1 行ずつ入力して Enter を押すのと同じ動作)。「挿入」は改行を含めそのまま入力欄に置くだけです
- **キーボードショートカット登録**(Ctrl / Alt / Meta を含む任意のキー)で、シェル表示中にワンキー実行
- **クイックボタン表示**: 各ワークフローを「シェル表示のクイック起動バー」にボタンとして常時表示できます
- **グループ管理**: 各ワークフローに「グループ」を割り当てて分類できます。グループは `/` 区切りで階層化でき(例: `Deploy/Staging`)、パネルはグループごとの見出しつきで表示されます
- **並べ替え**: 同じグループ内のワークフローを、カードの ▲ / ▼ ボタン、またはカード右下のグリップ(⠿)を掴んでの**ドラッグ&ドロップ**で並べ替えられます。ドロップ位置はカード端のアクセント線で表示されます(並び順は保存されます。別グループへのドロップは受け付けません)
- **書き出し / 取り込み(チーム共有)**: ワークフロー一式をバージョン付き JSON に書き出し、別マシンで取り込めます(Git リポジトリで共有する運用を想定)。取り込みはチェックリストで選択でき、既存(名前+コマンド一致)は「(登録済み)」表示で既定除外、既存とショートカットが重複する場合はショートカットを外して取り込みます。id は書き出し時に除去され、取り込み時に新規採番されるため既存を誤って上書きしません
- **右クリックの階層メニューから実行**: ターミナルを右クリックするとワークフローのグループが階層(フライアウト)メニューになり、グループをたどって目的のワークフローを実行できます(クリックで実行 / Shift+クリックで挿入のみ)。→ / ← / ↑ / ↓ / Enter / Esc のキーボード操作にも対応。右クリックしたペインに対して実行されます
- 初回起動時にサンプルワークフローを登録

### 起動セット(いつも開くシェル+ワークフローの一括初期化)
- ヘッダー「起動セット」タブで登録・管理。名前と、上から順に開く「項目」のリストを持ちます
- 各項目は **ローカルプロファイル または SSH ホスト** のどちらかを開き、任意で **ワークフローを自動実行**(実行モード)します
- 「起動」を押すと、登録順に 1 つずつスレッドを作成し(SSH 項目でパスワードが必要な場合はその場でプロンプトが出ます — パスワードは保存されないため自動化できません)、各スレッドの準備ができ次第そのワークフローを実行します
- プロファイル/ホストが削除済みの項目や、SSH 接続をキャンセルした項目はスキップされ、別のスレッドに誤ってワークフローが実行されることはありません
- 新規スレッドの ▾ メニューとコマンドパレットからも直接起動できます

### SSH 接続管理
- ホスト(名前 / ホスト / ポート / ユーザー / 認証方式)を登録・管理
- **`~/.ssh/config` からの取り込み**: SSH パネルの「~/.ssh/config を取り込み」で、既存の `Host` エントリ(`HostName` / `User` / `Port` / `IdentityFile`)を候補一覧から選んで一括登録できます。登録済み(ホスト+ポート+ユーザーが一致)の候補は「(登録済み)」と表示され既定で除外。`User` の無いエントリは ssh と同様にローカルのログイン名を補います(ワイルドカードの `Host` パターン・`Match`・`Include` は対象外)
- 認証方式: パスワード / 秘密鍵ファイル(パスフレーズ対応)/ ssh-agent / **秘密鍵 + パスワード併用**(`AuthenticationMethods publickey,password` のような多段認証。公開鍵で認証後、サーバが要求すればパスワードで認証を完了)
- **保存前に「接続テスト」**: ホスト編集画面から、到達性・認証・ホスト鍵(SHA256 フィンガープリント)を保存前に確認できます。テスト用パスワード / パスフレーズは保存されず、テストではホスト鍵を `known_hosts` に記録しません
- **パスワード・パスフレーズは保存されません**(接続時に入力し、その接続にのみ使用)
- 接続はタブとして開き、リサイズ・keepalive(30 秒)に対応
- **OpenSSH 互換の known_hosts 検証(TOFU)**: `~/.ssh/known_hosts` と照合し、記録された鍵と異なる鍵を検知した場合は MITM の可能性があるとして常に接続を拒否します。未知のホストへの初回接続時は、鍵種別と SHA256 フィンガープリントを表示する確認ダイアログが出て、承認すると鍵を `known_hosts` に保存した上で接続します
- **ローカルポートフォワード(`ssh -L` 相当)**: ホスト編集画面の「ポートフォワード」に `ローカルポート:リモートホスト:リモートポート`(例: `8080:localhost:80`)を 1 行 1 件で登録すると、そのホストへの接続時に自動で開始し、切断で停止します。リスナーは常に `127.0.0.1` にバインドし(LAN へ公開しない)、開始・失敗はターミナルにバナー表示されます。不正な書式は保存時に検出します
- **多段接続(踏み台 / ProxyJump, `ssh -J` 相当)**: ホスト編集画面の「多段接続」で、登録済みの SSH ホストを踏み台として接続順に選ぶと、それらを経由して目的ホストへ接続します。各段は前段の上に開いた `127.0.0.1` の direct-tcpip トンネルを通って接続する入れ子トンネル方式で、**ホスト鍵は段ごとに検証**します(未知の鍵は段ごとに TOFU 確認、記録済みと異なる鍵は常に拒否)。認証情報は接続時に**段ごと**に入力し、保存されません。ポートフォワードは目的ホスト側で動作します

### ウィンドウサイズ・位置の記憶
- 直前の終了時点のウィンドウサイズ・位置(最大化状態を含む)を記憶し、次回起動時に復元します(他の設定と同じくアプリ設定ディレクトリの JSON `window-state.json` に保存。プラグイン依存を減らすため `tauri-plugin-window-state` は使わず自前実装)

### セッション復元(前回のスレッド構成)
- 起動時に、前回開いていた**ローカルスレッドの構成(プロファイルと順序)**を自動で再作成します(既定オン。設定「起動 > 前回のスレッド構成を復元」で切替)
- SSH スレッドは認証が必要なため**自動再接続しません**。スキップした件数を起動時に通知し、SSH パネルや新規メニューから選んで接続します(パスワード等を保存しない方針のままです)
- レイアウトはスレッドの作成・終了のたびに `session.json` へ保存されます。プロファイルが削除されていた項目は既定プロファイルで開きます

### コマンドパレット
- `Ctrl+Shift+P` で起動。ワークフロー・SSH ホスト・アクション・**コマンド履歴**を横断ファジー検索
- `Enter` で実行、`Shift+Enter` で挿入のみ

### 永続コマンド履歴(スレッド横断)
- コマンドブロック(OSC 133)が完了するたびに、実行したコマンドを `history.json` に保存します。**ローカルでも SSH でも**マーカーを発行するシェルなら記録されます
- コマンドパレットから横断検索し、`Enter` でアクティブなスレッドで再実行、`Shift+Enter` で入力欄に挿入
- 同一コマンドは最新の 1 件に集約され、最大 2,000 件で打ち切り。コマンド文字列はプロンプト行から抽出するヒューリスティックです(プロンプト末尾 `$ ` / `❯ ` / `# ` / `% ` / `> ` 以降を採用)

### AI コマンド支援(プライバシー第一・自分の API キー)
- コマンドパレットの「**AI にコマンドを聞く**」で、やりたいことを自然言語で説明すると、環境(OS・シェル)に合わせたシェルコマンドを提案します
- **設定「AI コマンド支援」に自分の Anthropic API キーを登録した場合のみ有効**(空欄なら機能は完全に無効)。API 呼び出しはアプリから Anthropic API へ直接行われ、第三者のサーバーは経由しません
- **送信されるのは入力した質問と OS/シェル名のみ**。ターミナルの表示内容・コマンド履歴・ファイルは送信されません
- 提案されたコマンドは**自動実行されません**。編集可能な形で表示され、「ターミナルへ挿入」で入力欄にタイプされるだけです(実行は自分で Enter)。破壊的な操作には注意書きが付きます
- モデルは既定で `claude-opus-5`(設定で変更可能)。API キーはローカルの設定ファイル(`settings.json`)に保存されます — OS キーチェーン統合は今後の課題です

### 自動アップデート(配布経路ごとに管理を分離)
- 起動時に GitHub Releases の署名付きアップデートをサイレント確認し、新しいバージョンがある時だけ通知します(適用・再起動は毎回確認)。コマンドパレットの「アップデートを確認」で手動確認も可能
- 設定「起動 > 起動時にアップデートを確認」でオフにできます。署名検証は tauri-plugin-updater が強制します
- **入手経路ごとに更新の担当者が変わります**。アプリは起動時に自分がどう入ったかを判定し、担当者が別にいる場合は自分では更新しません:
  - ダウンロードした `.exe`(NSIS)/ `.msi` / `.dmg` / `.AppImage` → アプリ内アップデータ(**入れたのと同じ形式**にのみ更新)
  - Microsoft Store → Store が更新(アプリ内アップデータは**プラグインごと無効化**し、Store の更新画面を開く導線を出します)
  - `.deb` / `.rpm` / Homebrew → apt / dnf / brew が更新(理由を表示)
  - 開発ビルド → 何もしません
- 配信の有効化にはオーナーの署名鍵設定が必要です(手順: [リリース・自動アップデート・配布ガイド](../../.docs/release-and-distribution.md))。未設定のビルドではチェックは静かに何もしません

### Microsoft Store 配布(MSIX)
- Store は NSIS/MSI インストーラを受け付けないため、同じバイナリから MSIX を別途パッケージします(`scripts/build-msix.ps1` / `src-tauri/msstore/`)
- CI は Store の識別情報(リポジトリ変数 `MSSTORE_IDENTITY_NAME` ほか)が設定されている時だけ MSIX を生成し、`v*` タグではドラフトリリースにも添付します。詳細は[配布ガイド §4](../../.docs/release-and-distribution.md)

### 多言語対応(日本語 / English)
- 設定の「外観 > 言語」で **日本語 / English** を切り替えられます。UI 全体(タブ・パネル・ボタン・メニュー・モーダル・トースト・ショートカット一覧・ツールチップ)が即時に切り替わります
- ユーザーが入力したデータ(ワークフロー名・グループ名・タグ・ホスト名など)はそのまま保持されます(翻訳対象は UI の文言のみ)
- 文言は `ui/app.js` の `STRINGS` に日本語 / 英語のペアで一元管理し、静的な HTML は `data-i18n` 属性、動的な文字列は `tr()` で解決します。設定は他の設定と同様に JSON へ保存されます(既定は日本語)

## キーボードショートカット

修飾キーは OS に合わせて変わります。以下の表の **`Mod`** は **Windows / Linux では `Ctrl`、macOS では `⌘`** です。

| キー | 動作 |
| --- | --- |
| `Mod+Shift+P` | コマンドパレット(ターミナル外にフォーカスがある時は `Mod+P` でも開けます。ターミナル内の `Ctrl+P` はシェルの「前のコマンド」としてそのまま渡されます)|
| `Mod+Shift+T` | 新しいローカルスレッド |
| `Mod+Shift+W` | フォーカス中のスレッドを終了 |
| `Mod+Shift+D` | ペインの上下分割 / 分割解除 |
| `Mod+Shift+E` | ペインの左右分割 / 分割解除 |
| `Mod+Shift+B` | 入力ブロードキャスト(全ペインへ送信)の切替 |
| `Ctrl+Shift+C` / `V`(macOS は `⌘C` / `⌘V`) | 選択範囲をコピー / クリップボードから貼り付け |
| `Mod+Shift+F` | ターミナル内検索 |
| `Mod+Shift+↑` / `↓` | 上 / 下のペインへフォーカス移動(左右分割時は左 / 右)|
| `Mod+Shift+/` | キーボードショートカット一覧 |
| `Ctrl+Alt+↑` / `↓` | 前 / 次のコマンドブロックへ(要シェル統合) |

- シェル側の `Ctrl+K` などのキーバインドを潰さないよう、Windows / Linux のアプリショートカットは `Ctrl+Shift` / `Ctrl+Alt` 系にしています
- **macOS では `Ctrl` をアプリのショートカットに使いません**。`Ctrl+C`(SIGINT)・`Ctrl+D`(EOF)・`Ctrl+R`(履歴検索)などはターミナルに届くべきキーなので、アプリ側は `⌘` だけを使います。コピー / ペーストも macOS の慣習どおり `⌘C` / `⌘V` です

## ビルド方法

前提: [Rust](https://rustup.rs/) と、Linux の場合は Tauri のシステム依存パッケージ。

```bash
# Linux (Debian/Ubuntu) のみ必要
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev

# 開発実行
cargo install tauri-cli --version "^2"
cargo tauri dev

# 配布用ビルド (Windows: .msi/.exe, macOS: .dmg/.app, Linux: .deb/.rpm/.AppImage)
cargo tauri build
```

フロントエンドはバンドラ不要の静的ファイル(`ui/`)で、xterm.js は `ui/vendor/` にベンダリング済みです。npm は不要です。

GitHub Actions(`.github/workflows/build.yml`)で 3 OS のビルドを自動実行します。`v*` タグを push するとドラフトリリースに各 OS のインストーラが添付されます。

リリースの公開手順、自動アップデート(tauri-plugin-updater)の有効化、コード署名、winget / Homebrew での配布については [リリース・自動アップデート・配布ガイド](../../.docs/release-and-distribution.md) を参照してください(署名鍵や開発者アカウントなどオーナー側の準備が必要な項目をまとめています)。

## アーキテクチャ

```
crates/senju-core/   GUI 非依存のコア (cargo test でテスト可能)
  ├─ models.rs       Workflow / SshHost / Settings
  ├─ template.rs     {{placeholder}} の抽出・展開
  ├─ store.rs        JSON ファイル永続化 (アトミック書き込み)
  └─ sessions/       セッション管理
      ├─ local.rs    portable-pty によるローカルシェル
      └─ ssh.rs      russh による SSH シェル
src-tauri/           Tauri アプリ (コマンド定義・イベント転送)
ui/                  フロントエンド (xterm.js + vanilla JS)
```

- バックエンド → フロントエンドの出力は base64 で `session:data` イベントとして転送(マルチバイト文字が読み取り境界で分割されても壊れないようバイト列のまま渡し、xterm.js 側でデコード)
- 設定・ワークフロー・ホストはアプリ設定ディレクトリ配下の JSON(`workflows.json` / `ssh-hosts.json` / `settings.json`)

## セキュリティ上の注意 / 既知の制限

- SSH ホストキーは OpenSSH 互換の `~/.ssh/known_hosts` で検証します(TOFU)。記録済みの鍵と異なる鍵を提示するホストへは、たとえ「信頼」操作をしていても常に接続を拒否します(MITM 対策)
- パスワード・パスフレーズは永続化されませんが、OS のキーチェーン統合は未実装です
- コマンドブロックは OSC 133 シェル統合が前提の軽量実装です(ステータスチップ+コピー+折りたたみ+ブロック間ジャンプ)。折りたたみは xterm.js の描画レイヤーへの視覚的なオーバーレイで、実際の行を削除・非表示にするものではありません
- AI コマンド支援の API キーは平文の `settings.json` に保存されます(OS キーチェーン統合は未実装)。共有マシンでは注意してください
